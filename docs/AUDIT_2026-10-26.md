# Auditoría técnica y E2E, 26 de octubre de 2026

## Qué hace este repositorio

Es un MVP de liquidación de sueldos argentino. Tiene un motor DSL determinista,
persistencia multiempresa, API FastAPI, UI web, exportadores PDF/TXT, importadores
CSV/XLSX y un flujo de IA que propone reglas pero no las publica solo.

**Carga asumida:** un estudio contable pequeño o mediano, varias organizaciones y
empresas, uno o pocos procesos, SQLite en local y PostgreSQL en servidor. No se
asume un sistema de nómina masiva de miles de usuarios concurrentes.

## Must fix, ya corregido

1. **Liquidación con fórmulas no aprobadas** (`app/services/payroll_calculation.py`)
   - **Qué era:** el cálculo tomaba fórmulas `VALIDATED` y `APPROVED`.
   - **Problema:** una fórmula validada pero no aprobada podía afectar una liquidación real.
   - **Fix:** solo `APPROVED`. Test incluido.
   - **Si se omitía:** una regla sin aprobación humana producía recibos y exportaciones.

2. **Cambio de contraseña no invalidaba sesiones** (`app/auth/security.py`, `app/api/auth.py`)
   - **Qué era:** el token cambiaba de nonce, pero el servidor no lo comparaba con nada.
   - **Problema:** una cookie robada seguía funcionando después del cambio de contraseña.
   - **Fix:** `User.session_version`, incluida en el token y validada en API y web. Migración `c21f48a6d9e3`.
   - **Si se omitía:** el cambio de contraseña no expulsaba al atacante.

3. **CUIT de empresa único globalmente** (`app/database/models.py`)
   - **Qué era:** `companies.cuit` era único en toda la base, no por organización.
   - **Problema:** dos organizaciones no podían registrar la misma empresa.
   - **Fix:** unique `(organization_id, cuit)` en modelo y migración.
   - **Si se omitía:** el modo multiempresa fallaba para clientes compartidos.

4. **Escrituras normativas globales con rol editor** (`app/api/agreements.py`, `app/api/normative_packages.py`)
   - **Qué era:** un editor podía crear o modificar convenios globales y cargar paquetes normativos.
   - **Problema:** un usuario de una organización cambiaba datos usados por todas.
   - **Fix:** escrituras de convenios y carga normativa solo `admin`; lectura sigue disponible.
   - **Si se omitía:** un editor podía alterar escalas o convenios de otro cliente.

5. **Versionado de fórmulas bloqueaba correcciones** (`app/api/formulas.py`)
   - **Qué era:** cualquier versión nueva que solapara la vigencia anterior devolvía 409.
   - **Problema:** no se podía corregir una fórmula para el mismo período.
   - **Fix:** se permite la versión nueva; el cálculo usa la versión aprobada más alta.
   - **Si se omitía:** la única salida era dejar un hueco de vigencia o editar datos históricos.

6. **Empleados egresados podían liquidarse** (`app/services/payroll_calculation.py`)
   - **Qué era:** se filtraba por `active=True`, no por `termination_date`.
   - **Problema:** un egresado con `active` mal mantenido entraba en la corrida.
   - **Fix:** se excluyen los egresados anteriores al período. Test incluido.
   - **Si se omitía:** recibos y aportes de empleados que ya no trabajaban.

7. **La UI podía caer a una fuente sin scoping** (`app/web/routes.py`)
   - **Qué era:** si no se resolvía la organización, devolvía la fuente SQL global.
   - **Problema:** una inconsistencia de datos podía mostrar empresas de otra organización.
   - **Fix:** falla cerrado con una fuente vacía. Test incluido.
   - **Si se omitía:** fuga de datos entre organizaciones.

8. **El build Docker enviaba 344 MB de evidencia cruda** (`.dockerignore`)
   - **Qué era:** el contexto incluía todos los PDFs de investigación.
   - **Problema:** builds lentos y una imagen innecesariamente grande.
   - **Fix:** se excluye `normative/cct/evidence/` del contexto.
   - **Si se omitía:** cada build copiaba cientos de PDFs que la app no usa.

9. **Ruta del catálogo fallaba dentro de la imagen** (`app/api/normative_packages.py`)
   - **Qué era:** la ruta se resolvía desde el paquete instalado, no desde `/app`.
   - **Problema:** `normative/cct/catalog.json` no se encontraba en Docker.
   - **Fix:** resolución relativa al directorio de trabajo, manteniendo el bloqueo de path traversal.
   - **Si se omitía:** la carga normativa no funcionaba en el contenedor.

10. **Neto negativo rompía con un constraint** (`app/services/payroll_calculation.py`)
    - **Qué era:** un neto negativo llegaba al `INSERT` y fallaba por `net >= 0`.
    - **Problema:** la corrida devolvía un 409 genérico, no un error por empleado.
    - **Fix:** se reporta como error de ese empleado antes de persistir.
    - **Si se omitía:** un descuento excesivo trababa la corrida completa.

11. **CUIT/CUIL sin dígito verificador en la API** (`app/api/schemas.py`)
    - **Qué era:** solo se validaba que fueran 11 dígitos.
    - **Problema:** se podían cargar identificadores fiscales inválidos.
    - **Fix:** validación con `normalize_cuit_cuil`; tests de rechazo.
    - **Si se omitía:** datos inválidos en recibos y exportaciones.

## Should fix, pendiente

12. **Selección de fórmulas multi-CCT incompleta.** El cálculo elige por organización y fecha, no por convenio, categoría ni `ruleset_id`. Dos CCT de la misma organización comparten el mismo conjunto de fórmulas.
13. **`ruleset_id` no se usa.** No hay snapshot inmutable del conjunto de reglas aplicado a una corrida. Los hashes y trazas ayudan, pero no reemplazan un ruleset aprobado.
14. **Novedades limitadas.** Se importan como `REMUNERATIVE`, sin naturaleza no remunerativa, y el período es `AAAAMM`. Una corrida quincenal puede tomar dos veces la misma novedad mensual.
15. **Semántica de escalas.** Algunas fuentes publican un total conformado, no el básico. `SalaryScale.base_salary` no distingue `amount_type`.
16. **Fórmulas CCT no cargadas.** Las 12 fórmulas de `normative/cct/formulas.json` están validadas y testeadas, pero no hay un seed que las cree en la base.
17. **F.931 interno.** La planilla usa `float` para celdas y no reproduce el formato oficial. No sirve para presentación.
18. **Rate limiting por proceso.** No se comparte entre workers y detrás de un proxy usa la IP del socket. Faltan MFA y recuperación.
19. **UI incompleta para el backlog.** No hay pantallas de importación, paquetes normativos, F.931 ni revisión de propuestas IA persistidas.
20. **Builds no verificados.** Docker y PyInstaller no se construyeron en este entorno. Los PDFs crudos de evidencia no se versionan por tamaño.

## Verificación

- `pytest`: 466 tests.
- `mypy app`: 84 archivos, sin errores.
- `ruff check .`: limpio.
- Alembic: cabeza `c21f48a6d9e3`, upgrade y downgrade SQLite OK.
- Seed demo idempotente.
- Smoke test con Uvicorn: health, login, UI, alta y cálculo de una corrida, descarga F.931,
  recibo PDF y simulación de vacaciones responden. El cambio de contraseña deja la cookie
  vieja en 401 y la nueva en 200.
- Catálogo real: 10 CCT, 191 documentos, 235 escalas verificadas, dry-run sin warnings en base limpia.

## No comprobado

- Aceptación real de archivos por ARCA.
- Corrección legal de cada escala o artículo.
- PostgreSQL en ejecución, concurrencia real y carga.
- Builds de Docker y PyInstaller.
- OCR de PDFs escaneados que no tienen capa de texto.

## Veredicto

La base es usable como MVP demostrativo y los riesgos más graves de autorización,
sesión y cálculo ya están corregidos. Antes de producción faltan el filtro
multi-CCT, el snapshot de reglas, la validación ARCA y la integración de las
liquidaciones especiales en el flujo principal.
